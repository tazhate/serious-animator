# Ревью ashishjamarkattel/Animator

Разобран коммит `3e84695` (12.10.2026): около 4300 строк Python, пайплайн на Gemini, движок рисования, FastAPI с биллингом через Supabase. Ниже то, что ломается, и как это закрыто в порте. Пути и строки - по апстриму.

Статусы:

- **конструкция** - в порте проблема не может возникнуть, потому что устроено иначе;
- **исправлено** - та же логика есть, ошибка учтена;
- **выкинуто** - части нет в порте (API, биллинг, Gemini, CRAFT).

## Тайминг битов - главная беда оригинала

Весь сценарий одной сцены синтезируется одним запросом TTS, а потом `gemini/beat_timing.py` угадывает, где кончается каждая фраза.

| Где | Что ломается | Статус |
|---|---|---|
| `beat_timing.py:58-62` | Из пауз-кандидатов берется самая длинная, а не ближайшая к ожидаемой границе. Окна соседних границ перекрываются, и иконка второго бита рисуется под первую фразу. | конструкция: клип на каждую фразу, граница = длина клипа в сэмплах |
| `beat_timing.py:62-64` | Запасная граница не сравнивается с началом окна. Получается окно `[6.0, 5.5]`, движок латает это до 0.05 с, иконка мигает, шкала идет назад. | конструкция |
| `beat_timing.py:57` | Оценка по доле символов включает тишину в начале и в конце, все границы съезжают. | конструкция; тишина по краям каждого клипа обрезается (`audio.TrimSilence`), паузы между битами одинаковые |
| `beat_timing.py:27` | Порог тишины 3% от самого громкого кадра: один щелчок, и пауз не находится вовсе. | конструкция |
| `beat_timing.py:21`, `narration.py:28` | Формат аудио принимается на веру (PCM 24 кГц), MIME не читается. Другая частота - все окна неверны, нечетная длина - `ValueError`. | исправлено: любой ответ TTS декодируется ffmpeg в s16le 24 кГц моно, длительность считается по сэмплам |

## API и кредиты

Сервера в порте нет, поэтому весь блок **выкинут**. Если сервер когда-нибудь понадобится, вот что в оригинале надо чинить первым:

- `routers/generate.py:33` против `:38`: стоимость считается по первому чтению строки, рендер идет по второму. Пользователь, которому RLS разрешает править свою строку, платит за 1 сцену и получает 50.
- `generate.py:33-34`: `scenes` из строки, которую вставил браузер, не проверяется. Отрицательное число дает отрицательную цену.
- `generate.py:34`: ошибка Supabase после захвата строки оставляет ее в `generating` навсегда, каждый повтор получает 409.
- `jobs.py:45-49`: `_finish` внутри `try`. Сбой частичного возврата превращается в полный возврат при готовом видео, сбой записи статуса теряет кредиты.
- `jobs.py:39`: ожидающие задачи занимают потоки общего пула Starlette (40 штук). При 40 задачах в очереди перестают отвечать все эндпоинты, включая `/health`.
- Очередь только в памяти: рестарт посреди рендера оставляет списанные кредиты без возврата.
- `supabase.py:25`: любой не-200 от Supabase auth превращается в "сессия истекла", во время сбоя Supabase фронт разлогинивает пользователей.

## Что сознательно не перенесено

CRAFT (модель 83 МБ через onnxruntime), скелетизация, k-means по цветам, разбор растровой картинки на компоненты. Все это нужно, только чтобы восстановить штрихи из готовой картинки. Когда сцена изначально векторная, штрихи известны. Плата за это - стиль: Claude рисует проще, чем модель генерации изображений. Растровый режим можно добавить позже отдельным движком за тем же интерфейсом сцены, если этой простоты окажется мало.
